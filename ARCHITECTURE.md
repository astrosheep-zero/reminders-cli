# Reminders CLI POC — implementation authority

## Scope and acceptance
Implement native Reminders CLI and MCP stdio frontends, not Notes, GUI, agent configuration, a backend daemon, or a database reader. References at ~/playground/reminders/apple-mcp and ~/playground/reminders/remctl are read-only architectural/API evidence, not dependencies; they remain outside this repository. Independently implement code; do not copy unlicensed reference implementations. The facade/MCP revision must reduce production source below its 4,819-line starting worktree, including comments/blanks and excluding tests/dependencies; never compress formatting to meet that requirement.

Two peer frontend modules (ReminderCLI, ReminderMCP) share ReminderFacade; Runtime, Core and Native retain their independent responsibilities. Small C/Objective-C targets are implementation boundaries, not extra business layers. Swift 6.2+ / macOS 26+ / Apple silicon. Foundation/EventKit allowed; no SwiftUI. ReminderMCP uses official modelcontextprotocol/swift-sdk exactly 0.12.1. Collections is constrained to 1.6.0 so the dependency graph does not silently raise the compiler floor to Swift 6.4; Package.resolved records the complete graph.

## Process and ownership
One executable, `reminder`, in a minimal signed Reminder.app; normal mode is CLI, `reminder mcp` is a long-lived stdio frontend session, and internal `--worker` is the one-shot backend. CLI and MCP both use the facade's operation registry, schemas, typed dispatch and output mapping; MCP never shells out to CLI commands. The facade sends typed worker requests through Runtime. Each worker decodes, constructs Core Operations with Native backend, executes once, replies and exits. Private responsibility/sandbox SPI lives exclusively in RuntimeShim. ReminderKit selectors/ABI/objects live exclusively in ReminderKitShim. Native Swift translates bridge payloads and Core value types; Core knows neither shim nor EventKit. No backend daemon/socket/retry service.

Runtime transfers opaque bytes; it does not import Core. Facade owns worker encoding and validates final typed responses. The internal Codable enum representation is not a public input/output contract. One stdin request, stdout newline-delimited Runtime frames: handshake with buildID, mutationStarted (before first actual mutation), result with base64 payload. Native diagnostics go to stderr, never stdout. Worker startup and errors prior to mutation are definite failures; after mutationStarted, missing/malformed/truncated final answer or deadline => outcomeUnknown. Conservative unknown is acceptable, false definite-failure is not. Completion of save is local-system acceptance, NOT proof of remote iCloud delivery. No automatic retry of writes.

Use bounded stdin/stdout/stderr and wall time; cap request/result at 16 MiB, stderr 64 KiB. Default deadline 30 seconds, setup 120 seconds. Spawn same resolved executable with disclaimed responsibility, closed unrelated descriptors and stripped DYLD_* environment. If disclaim SPI unavailable/fails, fail explicitly rather than silently borrowing caller permissions. Build ID is injected at packaging; handshake mismatch before dispatch refuses. Do not claim cryptographic isolation from same-user attackers; this is a crash/permission boundary.

## Core interface policy
Core defines public Codable Sendable value models, Command enum, Result/Failure and ReminderBackend protocol. Core worker Operations.execute(command) is synchronous/serialized. Backend uses concrete typed methods, not generic selector invocation. Name resolution is exact-name or case-insensitive UUID; ambiguous names fail. Values preserve calendar date versus local date-time, no accidental midnight/timezone shift. Changes distinguish absent, set, clear (explicit Change<Value> enum). Enumerate enums rather than arbitrary Any dictionaries outside Native.

Feature families: reminder find/show/create/update/complete/delete/restore; lists/groups; sections; tags; smart lists with explicitly modeled filters and opaque unknown filter fields preserved on read; repeat rules; due/start/early/location/contact reminders; images; assignment to already joined shared-list members; template list/create/use/delete. No invitations. Native limitations must fail `unsupported` explicitly, never return fabricated success or empty data. CLI reference features can be staged through contracts, but final coverage matrix must disclose any missing capability.

The facade's single schema definition drives MCP input discovery, strict unknown/null/type validation and conversion to typed Core values. Public enums use `kind` plus named values (`value` for an unlabeled payload), never Swift's `_0`. The same codec converts public output, including opaque unknown smart filters on read only. CLI argument/image-file adaptation and human text remain CLI responsibilities. See docs/facade-api.md.

MCP data calls use a serial DispatchQueue, not the SDK's receive actor. Cancellation handlers pass a per-request RuntimeCancellation into Runtime; canceled queued requests cannot spawn later. EOF or signals stop the SDK transport, cancel pending/in-flight calls, and wait for Runtime to terminate/reap workers. Cancellation is advisory, never rollback: an accepted save or lost final response after a possible mutation remains unknown. No automatic retries and no setup tool, resource, prompt or generic native RPC.

Version token = deterministic hash of canonical visible mutable fields (include early alerts and all fields exposed for editing); not Swift Hasher, not only timestamp. A token check is optimistic read/check/save, NOT an atomic cross-device CAS. Recheck immediately before mutation. Backend by-ID read should use native lookup; do not force whole-account scan for each ID unless API lacks it, and document fallback. Mutations with multi-step failure return unknown or truthful partial evidence, not a definite no-write failure. No clone/delete cross-list fallback. Refuse moving a parent with children, nesting >1 level, self-parent, cross-list parent, invalid section/neighbor, unknown enum values. List/group/template destructive operations need explicit confirmation parameter; CLI --yes. Parent delete explicitly includes known children in one save. Single-process operations serialized; native store not assumed thread-safe. No batch command required in POC; operations that affect many records report count and stop on uncertainty.

Stable error codes: invalidInput (exit 1), notFound/ambiguous/conflict (2), permission/sandbox (3), unsupported (4), outcomeUnknown (5), backend/io/internal (6). Structured JSON output: {status:ok|failed|unknown, result?:..., error?:{code,message}, warnings:[]}; no localized-string branching. Human text succinct, JSON machine stable.

## Deletion journal
No SQLite or FDA. `deleted` means only this CLI's known deletes; output scope=toolOnly, never all-system Recently Deleted. Journal under ~/Library/Application Support/RemindersCLI/deleted.json; injected path for tests. Entry id,title,listID,parentID,time and pending/confirmed state. Lock read-modify-write across processes (flock on a sibling lock), atomic replacement, restrictive permissions. Persist intent successfully BEFORE deletion; failure aborts without calling backend. Reconcile journal with backend restorable-by-ID query; never infer absence on error, never erase evidence on unknown. Keep interrupted/pending intent for reconciliation. Recovery reads use saved IDs; records expire on successful reconciliation or documented 31-day retention. Restore target from journal or explicit --list; absent both => refuse (do not silently choose a default list). Restore confirmation must not compactMap away read failures. No permanent purge.

## Permissions, packaging, live safety
Only Reminders full access. setup alone requests authorization; doctor and normal commands diagnose without surprise prompting. Minimal .app and exec wrapper (not symlink). No FDA, Automation, Accessibility, Contacts, location access, privileged entitlements, or root. Coordinates/phone/email are explicit inputs, not fetched from system stores. Image frontend reads bytes; worker stages its own private temp file, passes native attachment URL, cleans up only once consumption safely completed. Do not promise frontend file reads bypass macOS folder permissions; CLI itself can still encounter them.

Build script may ad-hoc sign local dist output and clearly state unstable TCC identity; stable existing SIGNING_IDENTITY optional. Do not install certs, change keychains/TCC/settings, launch GUI, install to Applications/PATH, or run setup automatically. No real-data writes during unattended verification. Live smoke is explicit opt-in and restricted to unique POC test lists; include receipts and clean only fixtures created by that run, never name-only broad deletion. Cross-device sync needs human observation; report not verified if not observed.

## Contract decomposition
1 Core: typed operation engine + journal, independently accepted with fake-backend tests.
2 Runtime: bounded one-shot disclaimed worker transport + minimal packaging plumbing, independently accepted with fixture subprocess tests. Does not depend on Core implementation.
3 Native: concrete ReminderKit adapter conforming to accepted Core API; depends on Core. Isolated bridge/runtime API evidence and real-build verification, live behavior explicitly unverified absent permission-approved test.
4 CLI integration: executable commands, worker composition, packaging/docs/guarded smoke and coverage matrix; depends on accepted Core, Runtime, Native. Full CLI acceptance needs integration; do not mark native behavior live-verified from a fake backend.

## Verification

Official SDK client/server tests exercise initialize, tools/list, tools/call, structured/text results, cancellation, and the actual stdio executable using only invalid/no-store calls. Injected subprocess workers run the real facade/Core/Runtime paths for deterministic mutation/result/cancellation tests. No tests that access actual reminders, request permission, or alter user data by default. Tests cover main branches: journal failure stops deletion, stale versions, unsupported versus empty, backend failure propagation, stateful crash/timeout classification, recurrence input validation, restore journal safety. Toolchain failure is reported as environment failure, never patched around by changing behavior. No test-only compatibility shims that recreate removed APIs.
